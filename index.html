Design notes

  1. Worst line first. Lines are sorted by severity. Status is a word plus a color, so it still reads for color-blind people and on a dim shop-floor screen.
  2. One sentence before any number. A shift lead has seconds, so the headline says what changed, since when and why.
  3. Same incident, two depths. Frontline sees the decision first. Process experts see the evidence, the causal graph and a virtual experiment. Nobody gets a dashboard built for someone else.
  4. Control limits and a forecast. Dashed limits separate noise from a real process shift. The green dashed line shows what the recommended change should do, so the decision has a visible expected outcome.
  5. Show the reasoning. Causes are ranked by contribution and each opens its evidence. The causal graph shows how the parameters connect. People act on AI output when they can check it.
  6. Try before you change the line. The virtual experiment lets an expert test a setpoint and see the predicted scrap and savings. The recommendation updates with it, and a person always approves the change.
